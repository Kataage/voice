# v0.3 Core Profile and LFM → Irodori contract

This document defines the v0.3 backport from the canonical Issue #36 contract.
It is intentionally training-strategy independent: v0.3 keeps its existing
LFM LoRA plus Irodori Speaker Inversion/LoRA architecture. No v0.4
full-model TrainingPlan/Executor/publication architecture is required here.

## Runtime ownership

```text
core_profile.yaml + bounded conversation history + current user prompt
                              ↓
                           LFM
                              ↓
       {text, voice: {caption, emotion, events}}
                              ↓
                 canonical normalization/validation
                              ↓
                           Irodori
```

The Core Profile is persistent runtime conditioning. It is not model weights,
episodic memory, or a replacement for learned conversational style.

| Input or field | Owner and meaning |
| --- | --- |
| Core Profile | Stable identity, self-concept, first-person/addressing, facts, relationships, boundaries, and optional expression tendencies. |
| Learned persona behavior | LFM weights: diction, phrasing, rhythm, natural habits, and context-sensitive style. |
| Conversation history | Current dialogue context only; it cannot rewrite immutable profile facts. |
| `text` | Spoken words. It must be non-empty after normalization except for an explicit supported non-verbal-only plan. |
| `voice.caption` | LFM-planned acting/prosody guidance not expressible by coarse emotion/events. It is planned with `text`, not appended afterward. |
| `voice.emotion` | One existing coarse canonical emotion. Unsupported values normalize to `UNKNOWN`. |
| `voice.events` | Only explicit supported non-verbal events that should actually occur. Neutral turns commonly use `[]`. |

## Profile storage and compatibility

New personas receive `core_profile.yaml`. Its root is strict and versioned:

```yaml
schema_version: 1
identity:
  display_name: alice
  self_concept: "海辺の町で暮らす案内役"
  role: "相手の話を聞き、一緒に考える相棒"
  background:
    - "海の近くで暮らしている"
  first_person: "ぼく"
  preferred_address: "かたあげさん"
stable_facts:
  - key: home
    value: "海辺の町"
    immutable: true
relationships:
  - name: "かたあげさん"
    relation: "大切な会話相手"
    address: "かたあげさん"
    notes: ""
conversation_rules:
  - "分からないことは分からないと伝える"
expression:
  baseline_emotion: UNKNOWN
  tendencies:
    - "必要なときだけ明るさや真剣さを強める"
```

Profiles are deterministically serialized and have a SHA-256 fingerprint for
runtime provenance. A persona with no profile file gets a minimal default based
on its configured name. An invalid present profile fails closed rather than
silently changing identity.

Editing the profile is runtime-only. It is deliberately absent from Prepare,
Irodori, VC, and optimizer-checkpoint fingerprints. Existing full and LoRA LFM
artifacts therefore remain usable without mandatory retraining. The profile is
loaded on every `chat_turn()`, so an edit is visible on the next turn.

## System prompt contract

`build_lfm_system_prompt()` emits one deterministic bounded prompt that
explicitly separates profile, learned behavior, history, current prompt, and
output planning. It instructs the model not to repeat profile facts or force
non-verbal events merely because an expression tendency exists.

History is limited to the newest bounded set of user/assistant messages and a
bounded total size. The only system message is generated by PersonaVoice, so a
history item cannot insert a competing system instruction.

## Canonical expressive plan

The output object is exactly one JSON object with this shape:

```json
{
  "text": "spoken words",
  "voice": {
    "caption": "acting/prosody guidance",
    "emotion": "NEUTRAL",
    "events": []
  }
}
```

The current downstream vocabulary is reused without adding free-form labels:

- emotions: `HAPPY`, `SAD`, `ANGRY`, `NEUTRAL`, `FEARFUL`, `DISGUSTED`,
  `SURPRISED`, `UNKNOWN`;
- events: `Laughter`, `Cry`, `Breath`, `Cough`, `Sneeze`, `Applause`, `BGM`.

Aliases such as `laugh`, `sigh`, and `gasp` are normalized to the existing
canonical event (`Laughter` or `Breath`). Unknown event labels are dropped and
recorded as a diagnostic; they are never passed to Irodori. The normalizer does
not infer an event from words in `caption`, so mentioning laughter in prose
does not create a laugh event. A non-verbal-only response is valid only when
`text` is explicitly empty and at least one supported event remains.

## LFM boundary recovery

The LFM worker is bounded by `max_new_tokens`. Runtime validation occurs before
Irodori synthesis:

1. Normalize one model result.
2. On malformed, empty, wrong-schema, or degenerate output, make at most one
   repair attempt with a deterministic repair instruction and a smaller token
   bound.
3. A safe non-JSON spoken string may be recovered as plain text with neutral
   emotion and no events.
4. Empty output, missing/invalid spoken text, and clearly repeated output fail
   after the bounded retry. They never become an Irodori request.

The returned chat result contains the exact normalized plan in
`provenance.irodori_handoff`, plus profile/contract fingerprints, retry count,
recovery diagnostics, and bounded failure codes. Fallback never invents
laughter, breath, sigh, or any other event.

## Training/export alignment

New `export_lfm()` rows contain an `lfm_contract` marker with schema version and
`LFM_CONTRACT_FINGERPRINT`. Their system message is built by the same prompt
builder and their assistant completion uses the same output contract. Legacy
rows without the marker remain readable as historical data; a present but
incorrect marker makes the Prepare cache incomplete instead of silently
accepting a mixed contract.

The v0.3 training fingerprint records independent non-LFM and LFM scopes. A
deliberate LFM export/config/contract change removes only the derived LFM
adapter/checkpoints when the user explicitly runs training; Irodori, its
latents, and Seed-VC artifacts are retained. Other input or `--force` changes
keep the existing full invalidation policy. To regenerate only the LFM export
from an existing master dataset:

```text
uv run --locked persona export-lfm alice
```

This command does not run ASR, diarization, SenseVoice, or Irodori export.

## Deterministic comparison fixture

`tests/fixtures/persona_runtime_contract.json` contains the shared profile,
history, prompts, and expected semantic cases for v0.3/v0.4 comparison. The
same file is consumed by both lines; only the training method (for example
LoRA versus full SFT) should differ.

Hosted CI tests contracts, normalization, prompt construction, and handoff
without production model downloads. Real persona response quality, acoustic
rendering, and target-GPU behavior remain target-machine validation items and
must not be represented as completed by these tests.
