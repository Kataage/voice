# Final audit notes

This document records the additional correctness contracts verified after the deep-audit hardening merge. The upstream/model contract re-check began on 2026-08-22 and the hardware-runtime audit was extended on 2026-08-23 after real Windows/NVIDIA execution exposed architecture-specific failures that hosted CI could not reproduce directly.

## Audited upstream contracts

- Irodori-TTS is pinned to `8224dafb46d0aba89209a8f905f1cb7e3299d9c1`, which was still the upstream `main` commit during this audit and is the v4.1-Small revision PersonaVoice targets.
- Irodori v4.1 Small reference-bank preparation is capped at the checkpoint's 120-second combined-reference limit; the default remains 40 seconds and shorter clean same-speaker clips are preferred.
- ASR is intentionally fixed to `Systran/faster-whisper-large-v3@edaa852ec7e145841d8ffdb056a99866b5f0a478`, with `model.bin` SHA256 `69f74147e3334731bc3a76048724833325d2ec74642fb52620eda87352e3d4f1`. Runtime configuration cannot silently select a different remote ASR model, and the isolated worker rejects a post-setup weight replacement even when the revision marker is unchanged.
- `pyannote/speaker-diarization-community-1@3533c8cf8e369892e6b79ff1bf80f7b0286a54ee` is loaded from the audited local snapshot and uses both regular and exclusive diarization plus speaker embeddings. The config, embedding, segmentation, and PLDA assets are individually SHA256-pinned and checked before pipeline load. The official model documentation supports loading the pipeline from a local directory for offline use.
- The conversation brain is exactly `LiquidAI/LFM2.5-1.2B-JP-202606@b31023f2d69b95fbd7876898f8de9fae90e8afbd`, with `model.safetensors` SHA256 `abf38960d3f37c2be7c946a9b6b06d23ed04a1afb8ac192aa3b491e3dcdcf325`, using the native Transformers checkpoint rather than GGUF/ONNX. The current model card identifies it as the Japanese-capable text-only chat checkpoint intended for native fine-tuning/inference and recommends `temperature=0.1`, `top_k=50`, and `repetition_penalty=1.05`; the worker follows those values without injecting an extra `top_p` cutoff.
- The pinned LFM2 implementation uses `self_attn.out_proj` for the attention output projection even though the current Liquid TRL documentation shows the stale spelling `o_proj`. PersonaVoice resolves exact loaded `.self_attn.{q_proj,k_proj,v_proj,out_proj}` module paths instead of blindly suffix-matching, so ShortConv's separate `out_proj` is not adapted by accident.
- SenseVoice normal inference and deep health are local-only. Only the explicit setup/download operation may contact ModelScope, and inference-critical assets are hash-verified before use.
- Seed-VC remains isolated on `51383efd921027683c89e5348211d93ff12ac2a8`; this was still upstream `main` during this audit. Reenact output is isolated per request to avoid deterministic upstream filename collisions.

## Persona-learning contracts

- LFM SFT data is exported as conversational `prompt` + `completion` examples rather than a single full-conversation `messages` field. The non-empty system/user context is conditioning input while the authorized non-empty assistant JSON reply is the completion; bundle and trainer preflights independently reject any role drift.
- `SFTConfig(completion_only_loss=True)` is explicit, and CI instantiates that option inside the committed LFM worker environment on both Ubuntu and Windows. This prevents system prompts and the other speaker's text from receiving persona-imitation loss.
- Deep LFM health loads the pinned model and verifies all four audited attention projections exist for every `full_attention` layer declared by `config.layer_types` before training is attempted.
- A finalized LFM persona adapter requires `adapter_config.json`, a non-empty PEFT adapter weight, and `.personavoice-base-revision` matching the pinned JP-202606 revision. Training and inference both reject partial adapters or adapters finalized against a different base revision.
- LFM training provenance includes the base revision, worker lockfile, training implementation, and the exact LFM model-contract helper source. Changing dependency or targeting semantics invalidates an old adapter rather than silently reusing it.
- Seed-VC fine-tune checkpoint ordering uses numeric step values. Because the pinned upstream trainer can initialize weights but resets its local iteration counter, PersonaVoice records cumulative progress in staged run-directory offsets and resumes from the highest recoverable cumulative checkpoint.

## Data integrity and reproducibility contracts

- Identical raw recordings placed under multiple filenames are represented once in the training pipeline; duplicate logical paths are retained in source inventory provenance.
- The compact 16-hex source ID is derived from SHA256, and a theoretical truncated-prefix collision between different full hashes is rejected explicitly rather than corrupting utterance IDs.
- With explicit identity references, a source whose best diarized speaker falls below `prepare.min_identity_similarity` is treated as a valid source that does not contain the authorized target speaker. Its non-target transcript rows remain available for provenance/context, it contributes no target training clips, and it is reported in `dataset/skipped_sources.json`.
- Structural diarization failures remain errors. If completed preparation contains zero usable authorized-speaker utterances, the prepare stage fails rather than publishing a false-success state.
- Prepare fingerprints include the absolute materialization root because exported downstream manifests contain local absolute paths. Moving the repository/persona therefore invalidates prepared exports and regenerates them at the new location.
- Prepare cache policy includes the audited ASR revision/weight contract, pyannote revision/asset-hash contract, SenseVoice asset hashes, isolated worker lockfile hashes, and relevant preprocessing source hashes. Training fingerprints include Irodori/LFM/Seed-VC source/model contracts, lockfile hashes, and relevant training implementation hashes. Dependency or implementation changes therefore invalidate stale derived artifacts even when user input is unchanged.
- `persona.yaml`'s embedded persona name must match its containing persona directory. In the public repository configuration, real persona YAML files are ignored by default together with raw media, generated datasets, models, outputs, and runtime state.
- Training and runtime workers fail closed on missing/wrong audited model revisions and on audited critical-weight checksum mismatches rather than falling back to a network model or trusting a stale revision marker.
- A training component that is explicitly enabled is not silently skipped for data shortage: LFM LoRA requires at least two valid conversational examples, and optional Seed-VC fine-tuning requires at least two target-speaker clips.

## Runtime robustness contracts

- API generation endpoints use a single-flight lock by default so TTS/VC/LLM workloads do not concurrently contend for the same local accelerator and trigger avoidable OOM failures.
- Each Seed-VC reenact request owns a unique output directory, preventing concurrent or repeated conversions from confusing upstream deterministic filenames.
- LFM structured voice plans are normalized before synthesis so malformed `caption`, `emotion`, or `events` field types do not leak into the TTS command contract.
- A stale Seed-VC readiness marker is removed when an offline deep load proves the materialized assets are incomplete; setup may then explicitly repair that model state.
- Setup reuses ASR, LFM, and pyannote snapshots only when required files are present, the exact audited revision marker matches, and the audited SHA256 contract passes. Same-revision corruption therefore triggers exact-revision re-materialization instead of reuse.
- ASR and LFM workers re-hash their critical weight immediately before model load; pyannote re-hashes all pinned pipeline assets before load. An explicit worker download publishes `.personavoice-revision` only after checksum verification succeeds.
- Setup can discard and rematerialize only model views that fail deep offline verification while preserving shared download caches. CUDA visibility/runtime errors are not misclassified as corrupt model files.
- NVIDIA backend selection is architecture-safe rather than name-based. PersonaVoice resolves the physical GPU exposed as logical CUDA device 0 under `CUDA_DEVICE_ORDER=PCI_BUS_ID`, honors supported `CUDA_VISIBLE_DEVICES` ordinal/UUID remapping, reads compute capability from `nvidia-smi`, and matches only explicitly audited architectures. Unknown/MIG/unresolvable selections fail closed rather than guessing. UUID selectors accept an exact UUID or an unambiguous prefix; malformed values with appended garbage are rejected rather than matching a shorter physical UUID accidentally.
- The audited PyTorch 2.10 x86_64 policy uses `cu126` for Pascal/Volta-class hardware that cannot safely run the modern wheel and `cu128` for Turing-and-newer architectures explicitly present in the audited matrix. Unknown future architectures and unaudited host architectures fall back to CPU until the complete stack is audited.
- Seed-VC remains intentionally isolated on its older Torch 2.4/cu124 contract. A GPU that is supported by the main cu128 stack but not by the Seed-VC stack (for example an audited Blackwell capability) keeps the main workers on CUDA while Seed-VC alone falls back to CPU.
- CUDA setup records the selected physical GPU UUID, compute capability, and NVIDIA driver version only after real CUDA smoke tests succeed inside Irodori and each selected PyTorch worker environment. The preflight executes FP32 and FP16 kernels on every CUDA environment, additionally executes BF16 matrix multiplication on Ampere-or-newer devices, and checks that worker device 0 reports the same capability selected by the root hardware policy.
- A physical GPU replacement, a `CUDA_VISIBLE_DEVICES` change that selects another physical device 0, disappearance of the CUDA GPU, or an NVIDIA driver-version change invalidates direct CUDA model execution until `persona setup --backend auto` reruns the real-kernel preflight. Compatible locked environments and already verified model assets may be reused; a hardware re-preflight is not equivalent to re-downloading/retraining everything.
- ASR does not assume that CUDA implies float16. CTranslate2's actual supported compute types are queried at runtime; explicit unsupported compute types fail, while automatic CUDA selection chooses the safest supported type and can fall back to CPU during setup verification when the CUDA runtime itself is not usable.
- Irodori training precision is capability-aware. The audited `cu126` path uses fp32 with TF32 disabled, and Turing `cu128` also uses fp32/no-TF32 because Turing lacks BF16/TF32. Ampere-and-newer audited `cu128` devices retain the pinned model's native bf16 + TF32 path. Unknown capability fails closed to fp32/no-TF32. LFM independently gates BF16 on both Ampere-or-newer capability and PyTorch's runtime BF16 support; older CUDA devices use fp16.
- TTS candidate batching follows the VRAM of the physical GPU actually exposed as logical CUDA device 0. An unrelated larger GPU elsewhere in a multi-GPU host can no longer cause PersonaVoice to over-batch the selected smaller device, and both audited `cu126` and `cu128` paths use the same selected-device policy.
- Windows setup materializes the exact Gyan shared FFmpeg 8.1.1 archive into gitignored `.runtime/tools` from its versioned official release URL and verifies the archive SHA256 independently published in Microsoft's WinGet `Gyan.FFmpeg.Shared` 8.1.1 manifest. Download size, archive file count/uncompressed size, path traversal, drive-like names, symlink entries, and case-insensitive duplicate paths are bounded or rejected before publication.
- The pinned Windows FFmpeg runtime records and re-verifies the exact SHA256 inventory of every regular file under its `bin` tree, not only the primary executables or well-known FFmpeg DLL families. Missing, modified, injected, symlink/junction-backed, or otherwise untracked runtime files fail closed. A present-but-invalid pinned runtime is never silently bypassed in favor of a different PATH runtime. Normal build/inference/doctor paths do not download FFmpeg; only explicit setup may repair/materialize it.
- Diarization preloads local audio through the audited PersonaVoice FFmpeg resolver into a mono 16 kHz float32 waveform before calling pyannote. This removes TorchCodec file decoding from the diarization data path while keeping TorchCodec/FFmpeg load compatibility explicitly verified.
- The environment contract fingerprints runtime safety implementations (`hardware.py`, Irodori training policy, TTS inference batching policy, setup policy, FFmpeg resolver, pinned FFmpeg contract/materializer, CUDA preflight, worker launcher, and ASR runtime policy) in addition to pyprojects/locks. Updating safety logic therefore makes older setup state stale rather than authorizing old environments under new code.

## Locked dependency maintenance contracts

- Irodori's pinned upstream checkout is never permanently rewritten to add PersonaVoice GPU extras. Setup atomically overlays the audited `locks/Irodori-TTS.pyproject.toml` and managed lock only while synchronizing, records a crash-recovery marker, and restores the pinned vendor files in `finally`.
- Worker and Irodori locks contain CPU and all GPU extras setup may select: `cu126` and `cu128` for the PyTorch 2.10 workers, plus the isolated `cu124` Seed-VC stack.
- `scripts/lock_all.sh` and `scripts/lock_all.ps1` require the audited `uv 0.12.5` before regenerating dependency locks. They dry-run every permitted CPU/CUDA extra immediately after generation so a maintenance update cannot silently publish a lock that only works for one GPU generation.
- The POSIX and PowerShell maintenance scripts themselves are syntax-checked by CI on their native hosted OS families.

## Automated validation

`core-ci` has fourteen jobs: Ubuntu/Windows root jobs, five isolated worker jobs on each OS, and dedicated Irodori-lock jobs on both OSes. Root jobs perform locked sync, Ruff, the complete pytest suite, compileall, CLI smoke tests, and native lock-maintenance-script syntax validation. Worker jobs perform locked sync and compile checks; diarization verifies the pinned `torch/torchaudio 2.10.0 + torchcodec 0.10.0 + pyannote.audio 4.0.7` ABI contract, SenseVoice imports its real FunASR runtime, and LFM instantiates the required TRL training API.

The GPU dependency matrix is resolved without model downloads on both Ubuntu and Windows. Diarization, SenseVoice, and LFM validate both `cu126` and `cu128` locked extras; Seed-VC validates its isolated `cu124` extra; the dedicated Irodori jobs validate CPU, `cu126`, and `cu128` against the managed project overlay. GitHub Actions are pinned to audited commit SHAs rather than mutable major-version tags, and CI installs the fixed `uv 0.12.5` used to generate the audited locks.

The merge gate for this hardware-runtime revision is that every one of these fourteen jobs succeeds on the same final PR head after all source, lock, script, test, and documentation changes are present. Hosted runners do not provide the target NVIDIA hardware, so static architecture policy and dependency resolution are combined with extensive unit tests while the real dtype-aware CUDA-kernel preflight is executed by `persona setup` on the user's machine before model assets are accepted as ready.

## Remaining validation boundary

Repository CI can prove static policy, unit behavior, pinned dependency resolution, Windows/Linux import/ABI contracts, crash-safe setup state, and that real-target setup will execute CUDA smoke kernels before publishing a ready environment. Hosted CI still cannot physically execute every NVIDIA architecture/driver combination, nor can it prove end-to-end acoustic quality with the user's authorized media.

The final hardware acceptance gate therefore remains deliberate and explicit: after pulling the merged revision on the target machine, run `persona setup --backend auto` and `persona doctor --deep`. On a CUDA setup, these commands must complete the architecture/UUID/driver-aware, dtype-aware kernel preflight and offline model loads successfully. Then perform a real authorized `persona build` followed by TTS/VC/chat smoke inference. GPU or driver replacement later intentionally requires rerunning setup/preflight before direct model work; compatible environments and assets are reused where safe.

## Issue #26 fixed-dependency verification (2026-08-26)

The full-model executor implementation was rechecked against the clean v0.3.0 baseline and the exact pinned upstream/dependency environments, rather than only mocked training APIs.

- The clean `Aratako/Irodori-TTS@8224dafb46d0aba89209a8f905f1cb7e3299d9c1` checkout was synchronized from its committed lock under Python 3.10.20 with PyTorch 2.10.0, Transformers 5.12.1, and PEFT 0.18.1. Its real `train.py`, `infer.py`, and conversion CLI all imported successfully. A PersonaVoice full config was parsed through upstream `ModelConfig`/`TrainConfig`; full mode, held-out validation, best-checkpoint retention, and Ampere BF16/TF32 settings survived the real parser.
- Upstream `save_checkpoint` was exercised with a real PyTorch model, AdamW state, `ScalarLRScheduler`, dataloader state, and runtime state. A fresh process restored step 1, performed another optimizer/scheduler update, and wrote step 2. The audit exposed that upstream advances the scheduler before its public step counter, so native `last_step` is exactly `checkpoint step - 1`. PersonaVoice full and LoRA validators now accept that real invariant and reject an intentionally mismatched checkpoint without modifying any checkpoint bytes.
- The locked LFM worker was synchronized with PyTorch 2.10.0, Transformers 5.15.1, TRL 0.29.1, PEFT 0.20.0, and Datasets 4.8.5. The exact LFM tokenizer/chat template produced raw and TRL-processed prompt/completion lengths with identical non-empty completion masks. A tiny native LFM2 model completed validation/save cycles, produced a fully attested step-2 checkpoint, resumed it to step 3 with optimizer/scheduler/RNG state, finalized a portable full artifact, and loaded that artifact directly through the inference worker contract.
- Fixed-version execution found and corrected three API/format assumptions that mocks could not reveal: Transformers 5 does not accept `SFTConfig(save_safetensors=...)`; callbacks must inherit `TrainerCallback`; and tokenizer BPE merge strings beginning with `/` are tokens, not machine-local filesystem paths. Portable-path validation is now field-aware while Windows drive paths and path-semantic absolute/UNC/file-URI values remain rejected.
- Raw LFM examples are checked before TRL preprocessing, and processed `completion_mask` shapes are checked afterward. Prompt-prefix drift, zero-token completions, and any sample that would exceed the audited 2048-token sequence length fail before training instead of silently truncating all supervised labels.
- Irodori LoRA candidate finalization now copies only the upstream best-validation adapter config/weight to an atomic portable directory, strips machine-local base-path metadata, binds the selected filename's exact step/loss to provenance, and inventories every byte. Native final/periodic/best directories remain untouched for recovery and v0.3 compatibility.
- Remote bundle validation rejects Windows, UNC, file-URI, audio, and POSIX absolute paths even when they are embedded in LFM message text, while ordinary HTTPS documentation URLs remain transferable. Portable model verification requires the on-disk regular-file set to match its checksum inventory exactly; publication rollback restores the previous v0.3 artifact even when the new candidate installation fails after archival and before marker creation.

These are contract and small-model/native-state validations, not a claim that a paid Modal A100 job or a multi-hour full 1.2B/v4.1-Small persona training run was performed. Production acceptance still requires authorized held-out media, the local quality gate, and target-hardware/Modal execution as applicable.
